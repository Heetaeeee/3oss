## 2. 역할별 상세

### A 김권섭 — AI 세분화 · 블라인드 추정

- **서버는 단단함.** 한 명만 낸 상태에서 `GET /api/tasks` · `GET /api/estimates` 어디에도 값 · 근거가 없음. 확정된 작업 재제출 차단, 공개 유지(팀원이 늘어도), 공개 뒤 수정 버전 기록(같은 값 재제출은 안 쌓음)까지 동작
- **A-4 추정 화면 (`kwonseop/sizing-ui`, 미병합)** — 제출(이름만 공개) → 공개(값 · 근거 · 의견 차이 큼) → 고치기 · 수정 기록 → 확정(공개 뒤에만) → `n시간 확정` 배지. `textContent` 만 사용, 서버 오류 문장을 폼 아래에 표시
  - 알려진 한계: 데이터가 바뀌면 카드를 통째로 다시 그려 다른 카드에 치던 값이 지워짐 (코드에 `shortcut:` 으로 적어 둠)
- **A-5 · A-6 없음** — `/api/breakdown` 404, `src/lib/llm.js` 없음, `#breakdown` 패널 비어 있음. 중간발표 시연 "발표 준비를 AI로 나눠 등록"이 여기에 막혀 있음

### B 박지호 — 부담률 · 추천

- 부담률 막대, 추천(근거 문장 포함), 배정까지 화면으로 동작. 완료로 바꾸면 막대가 줄어드는 것 확인
- 서버 오류가 전부 한국어 JSON으로 통일됨 (깨진 JSON 400, 없는 경로 404, 본문 초과 413)
- **배포(B-6)가 아직 시작 전.** README에 배포 주소 없음. 최종 완성 기준("배포 주소 접속")에 걸림

### C 우희태 — 팀원 · 작업 · 진행

- 네 페이지 뼈대, 팀원 · 작업 등록 · 수정, 진행률 · D-day · 완료 작업 비중, 폼 오류를 서버 문장으로 표시, 완료 시각(`completedAt`) 기록까지 병합
- 주차별 수행률(추가 구현)이 세 브랜치로 쌓여 있음. `weekly-ui` 가 앞 두 개를 포함하므로 **`weekly-ui` 하나만 PR** 하면 됨
- 지침서의 테스트 개수(21개)가 실제(24개, 주차별 병합 시 30개)와 다름
