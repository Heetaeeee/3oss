## 4. 입장 코드(R1) — 시작 전에 합의할 것

공용 계약을 크게 바꾸므로 **11/20(목)까지** 아래를 정하고 `team/README.md` 에 적은 뒤 시작합니다.

**정할 것**

1. **팀원 수의 뜻** — 인원 상한인가, 추정 공개 기준인가. 제안: 상한. 공개 기준은 지금처럼 등록된 팀원 전원
2. **이름으로 다시 들어오면** — 같은 이름이면 같은 사람. 새 이름이면 팀원으로 새로 등록(가능한 시간은 나중에 입력). 상한을 넘으면 400
3. **코드 형식** — 영문 대문자 · 숫자 6자리, 헷갈리는 글자(0 · O · 1 · I) 제외
4. **방 코드를 보내는 법** — 제안: 요청 헤더 `X-Room-Code`. `api.js` 한 곳에서 붙임
5. **기존 데이터** — 지금 `data/db.json` 의 팀원 · 작업은 방 하나로 옮김

**서버 계약 (제안)**

```js
// data/db.json
{ rooms: { 'K7MQ2X': { name: '할래말래 팀', size: 3, members: [], tasks: [], createdAt } } }

// store.js — 라우트는 지금 쓰던 { members, tasks } 모양을 그대로 받는다
export function loadRoom(code)        // 없는 코드면 null
export function saveRoom(code, room)

// 각 라우트에서 바꾸는 줄
const db = load();          →  const db = loadRoom(req.roomCode);
save(db);                   →  saveRoom(req.roomCode, db);
```

| 경로 | 하는 일 | 담당 |
|---|---|---|
| `POST /api/rooms { name, size }` | 방 생성 → `{ code, name, size }` (201) | B |
| `GET /api/rooms/:code` | 입장 확인 → `{ code, name, size, memberCount }` / 404 | B |
| 나머지 `/api/*` | `X-Room-Code` 헤더 필수. 없으면 400, 없는 방이면 404 | B (공용 미들웨어) |

**지키는 원칙** — 비밀번호 · 개인정보는 받지 않습니다. 입장 코드는 "이 팀의 공간을 여는 열쇠"일 뿐 계정이 아닙니다. README 원칙 4의 "로그인이 없다" 문구는 이렇게 고칩니다.
