## 3. 역할별 완성도 · 피드백 · 앞으로의 구현 사항

### A 김권섭 — AI 세분화 · 블라인드 추정 (약 60%)

**잘 된 점**

- 블라인드 추정의 서버 · 화면이 모두 끝까지 동작함
  - 한 명만 낸 상태에서 어떤 API 응답에도 값 · 근거가 없음
  - 공개 유지, 버전 기록(같은 값은 안 쌓음), 확정 뒤 재제출 차단까지 됨
- 화면이 `textContent` 만 씀
- 확정칸은 공개된 뒤에만 그려서, 블라인드를 화면에서도 지킴
- 다시 그려도 입력하던 값이 남음

**피드백**

- 프로젝트가 "AI 도우미"를 내세우는데 AI 부분(A-5 · A-6)이 0%. 추정 쪽 다듬기에 시간이 많이 갔음. 이제부터는 세분화가 최우선
- 지침서와 구현이 어긋나기 시작함. 구현 PR에 지침서 수정을 같이 넣는 습관이 필요

**앞으로의 구현 사항 (순서대로)**

1. **A-5** `src/lib/llm.js` + `POST /api/breakdown`
   - 키가 없거나, 틀리거나, 시간 초과(8초)면 200 + `fallback`
   - 빈 제목은 400. 500은 내지 않음. 키를 로그에 찍지 않음
2. **A-6** 세분화 화면 (`#breakdown`)
   - 처음은 일반 패널로 (지금 마크업에 붙은 `panel--ai` 를 뺌)
   - 제안이 오면 노랑 패널 + 체크박스, 고른 것만 등록
   - fallback 이면 직접 입력
3. **#35 반영** — 추정 목록에서 상위 작업을 뺌 (`sizing.js` 의 `ordered` 필터 한 줄)
   - 선택: 추정 API에서도 상위 작업이면 400
4. **A-4 지침서 동기화** — 고치기 · 수정 기록 · 입력값 보존 · 확정 후 기록 보기 (문제 3)
5. **A-7 점검**
   - 키를 비운 서버, 틀린 키, 와이파이를 끈 상태
   - 같은 제목 5번 넣기, 이상한 입력 넣기
   - 프롬프트 다듬기
6. 시간이 남으면 "지난주 AI 요약"
   - C의 `completedAt` 은 이미 있음
   - 화면 자리 `#weekly-summary` 는 #27에 있음
