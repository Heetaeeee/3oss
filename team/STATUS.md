## 5. 입장 코드(R1) — B 가 뼈대, 이후 각자

### 정한 것 (11/19 김권섭 결정 — 팀 확인 필요)

1. **추정 공개 기준** — **등록 인원이 정원에 닿았고, 등록된 전원이 냈을 때** 공개. 정원이 차기 전에는 먼저 들어온 사람만 내도 공개되지 않음 — 나중에 들어온 사람이 이미 공개된 값을 보고 추정하는 것을 막기 위해서
   - 결원(한 명이 끝내 안 들어옴)이면 방 정원을 줄임: `PATCH /api/rooms/:code { size }` — 현재 등록 인원보다 작게는 못 줄임
   - 정원이 차면 새 이름으로 입장할 수 없음(400 `팀원 수가 다 찼습니다.`)
2. **같은 이름으로 입장** — **거부.** 400 `이미 같은 이름의 팀원이 있습니다.` 같은 사람이 둘로 보이거나 실수로 남의 이름으로 들어가는 것을 막음
   - **한계:** 서버는 누가 요청했는지 확인하지 않음. 팀원 id 는 목록 API 로 보이고 브라우저 저장값 · 요청 본문은 바꿀 수 있으므로, **마음먹고 남인 척하는 것은 막지 못함.** 보장하는 것은 "화면에서 다른 사람을 고르는 기능이 없다"까지
   - 막으려면 입장 때 서버가 비밀 토큰을 발급하고 추정 API 가 토큰으로 제출자를 정해야 함 — 마감 뒤 확장 (7장)
3. **다시 들어오는 사람** — 입장할 때 내 팀원 id 를 브라우저에 저장(`localStorage`)하고, 같은 브라우저로 다시 오면 이름 입력 없이 자동 입장
   - 한계: 다른 기기나 저장이 지워진 브라우저에서는 자기 이름으로 다시 들어올 수 없음. 시연은 각자 자기 기기 하나로 함
   - 저장된 id 가 삭제된 팀원이면 입장 화면으로 돌려보냄
4. **팀원이 생기는 길은 입장 하나** — 입장은 `{ name }` 만 받고 가능한 시간은 **0으로 시작**(배정 불가). 입장 직후 등록 · 진행 화면에서 내 가능한 시간을 넣으라고 안내. 기존 팀원 등록 폼과 `POST /api/members` 는 입장 코드를 켤 때 없앰 — 남겨 두면 정원 · 이름 검사를 건너뛰고, 대신 등록된 사람은 같은 이름 거부 때문에 아무도 그 이름으로 들어올 수 없음
   - 이름 · 정원 검사는 **공용 함수 하나**(C 의 `validate.js`)를 입장 · 이름 수정 두 경로가 함께 씀
5. **팀원 삭제와 추정** — 지울 때 서버가 한 번에 처리:
   - 그 사람이 담당인 작업 → `담당 미정`
   - 그 사람이 낸 추정 → 지우지 않고 남김(공개 계산에서는 빠짐). 이미 쌓인 수정 기록은 그대로
   - 정원 1 감소
   - 작업마다 공개 조건을 다시 봄 → 삭제로 공개 조건이 채워졌으면 **그 자리에서 공개 기록(`estimatesRevealed`)과 첫 버전을 남김** — 지금은 추정 제출 때만 기록하므로, 이 처리가 없으면 공개됐는데 기록이 없거나 다음 입장 때 다시 가려짐. 이 처리는 A 가 만든 순수 함수를 C 의 삭제 라우트가 부름

### 정할 것

6. **코드 형식** — 영문 대문자 · 숫자 6자리, 헷갈리는 글자(0 · O · 1 · I) 제외
7. **방 코드를 보내는 법** — 제안: 요청 헤더 `X-Room-Code`. `api.js` 한 곳에서 붙임

### 체험 방 — 평가자가 코드 없이 들어오는 방

**왜** — 최종 결과물이 배포 주소라, 평가자는 주소만 받고 처음 들어옵니다. 빈 방에서는 팀원 세 명 · 작업 · 세 명분 추정까지 혼자 해야 핵심 기능이 보입니다.

**하나를 같이 쓰지 않는 이유** — 첫 방문자가 마지막 추정을 내거나 작업을 배정 · 삭제하면 다음 방문자는 그 장면을 볼 수 없습니다. 하루 한 번 되돌리는 것으로는 "처음 온 사람이 공개 장면을 직접 본다"를 보장하지 못합니다. 그래서 **누를 때마다 새 체험 방을 만듭니다.**

| C | `members` · `tasks` · `progress` · `weekly` | 팀원 등록 폼 없애기, 머리말 팀명 · 이름 · `나가기` |

세 명이 다 바꾸면 B 가 **스위치를 켜고**, `load()` · `save()` 의 기본 방 처리를 지웁니다.

**지키는 원칙** — 비밀번호 · 개인정보는 받지 않습니다. 입장 코드는 "이 팀의 공간을 여는 열쇠"일 뿐 계정이 아니며, 신원 확인도 하지 않습니다(정한 것 2). README 원칙 4의 "로그인이 없다" 문구는 이렇게 고칩니다.

## 6. 배포 — AWS EC2 + Docker, 수동 배포

> **따라 하는 순서는 [DEPLOY.md](DEPLOY.md)** 에 있습니다 — 코드 준비부터 https 주소, 업데이트 · 백업, 막혔을 때까지.

**공지 (수업)** — 최종 결과물은 **배포된 서비스 주소(URL)**. Docker 배포는 **권장, 필수 아님**. Vercel 처럼 배포를 자동으로 처리하는 서비스는 쓰지 않음. (원문 링크 · 캡처는 맨 위 "근거 자료"에)

**정한 구성** — 7조가 같은 조건(Express · JSON 파일 저장 · 자동 배포 금지)으로 이미 배포한 구성을 따릅니다. 만든 순서가 [7조 docs/deploy.md](https://github.com/cjs1004ounds/oss-teamproject/blob/main/docs/deploy.md)에 있어 그대로 참고합니다 (11/19 내용 확인).

| 항목 | 선택 | 이유 |
|---|---|---|
| 서버 | AWS EC2 한 대 (서울 리전, t3.micro) | 가상 서버를 직접 운영 → 자동 배포 규칙에 맞음. 7조 가이드를 따라 할 수 있음 |
| 실행 | Docker 컨테이너, 메모리 512MB 제한 | 권장 사항. 의존성이 Express 하나라 `Dockerfile` 20줄 정도 |
| 데이터 | 컨테이너 밖 볼륨에 `db.json` (`DATA_DIR`) | 컨테이너를 새로 만들어도 데이터가 남음 |
| 주소 | 무료 도메인(duckdns) + nginx 로 https | 결과물이 주소라 기억하기 쉬운 주소와 https |
| 관리 접속 | **AWS Session Manager** (SSH 포트를 열지 않음). 안 되면 SSH 22번을 **내 IP 에만** 열기 | 수동 배포를 하려면 서버에 들어가야 함. 7조와 같은 방식 |
| 배포 | `main` 병합 뒤 서버에 접속해 직접 다시 빌드 · 실행 | 자동 배포 아님. GitHub Actions 는 테스트만 |

**쓰지 않는 것** — Vercel · Render · Netlify · Railway 처럼 GitHub 에 연결해 자동으로 배포하는 서비스. Render 무료는 재시작 때 파일이 지워지고 15분 쉬면 잠들어 평가자가 첫 화면을 1분 기다림.

**대안** — AWS 가입이 막히면 Oracle Cloud Always Free 가상 서버에 **같은 방식(Docker + 볼륨)** 으로 올림.

**알아둘 것**

- AWS 신규 계정의 무료 조건(크레딧 · 무료 플랜 기간)은 가입 전에 공식 페이지에서 확인하고, **예산 알림**을 꼭 걸어 둠
- 최종 결과물이 주소라 **평가가 끝날 때까지 서버가 켜져 있어야 함**
- `.env`(Gemini 키)는 서버에만. 저장소와 Docker 이미지에 넣지 않음

**순서 (B)**

| # | 할 일 | 언제 |
|---|---|---|
| 1 | `store.js` 저장 경로를 `DATA_DIR` 환경 변수로 바꿀 수 있게 (기본은 지금처럼 `data/`) + `Dockerfile` | 1단계 |
| 2 | 내 컴퓨터에서 `docker build` · `docker run`(볼륨 · `--memory 512m` · `TZ=Asia/Seoul`)으로 먼저 확인 | 1단계 |
| 3 | EC2 만들기 — 보안 그룹은 80 · 443 만(관리는 Session Manager), duckdns 주소 연결, nginx + https 인증서 | 2단계 첫날 |
| 4 | 서버에서 같은 명령으로 실행, `--restart unless-stopped` 로 재부팅해도 다시 뜨게 | 2단계 첫날 |
| 5 | 업데이트: 서버 접속 → `git pull` → 이미지 다시 빌드 → 컨테이너 교체 (수동) | 매 병합 뒤 |
| 6 | 하루 한 번 볼륨의 `db.json` 을 복사해 두는 백업 | 2단계 |
| 7 | README 에 배포 주소와 다시 올리는 법 | 2단계 |
