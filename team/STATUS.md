### 정한 것 (11/19 김권섭 결정 — 팀 확인 필요)

1. **팀원 수의 뜻** — 추정 공개 기준은 **현재 등록된 팀원 전원**(지금 동작 그대로). 방을 만들 때 고른 팀원 수는 **정원**으로만 씀 — 정원이 차면 새 이름으로도 입장할 수 없음(400 `팀원 수가 다 찼습니다.`)
2. **같은 이름으로 입장** — **거부.** 400 `이미 같은 이름의 팀원이 있습니다.` 남의 이름으로 들어가 추정을 내지 못하게 하기 위해서
3. **다시 들어오는 사람** — 입장할 때 내 팀원 id 를 브라우저에 저장(`localStorage`)하고, 같은 브라우저로 다시 오면 이름 입력 없이 자동 입장
   - 한계: 다른 기기나 저장이 지워진 브라우저에서는 자기 이름으로 다시 들어올 수 없음. 이어서 쓰기 기능은 범위가 커서 넣지 않음. 시연은 각자 자기 기기 하나로 함
   - 이름을 바꿔 새로 들어오면 팀원이 늘어 추정 공개가 그 사람을 기다리게 됨 → 그때는 P2 팀원 삭제로 정리

### 정할 것

4. **코드 형식** — 영문 대문자 · 숫자 6자리, 헷갈리는 글자(0 · O · 1 · I) 제외
5. **방 코드를 보내는 법** — 제안: 요청 헤더 `X-Room-Code`. `api.js` 한 곳에서 붙임
6. **기존 데이터** — 지금 `data/db.json` 의 팀원 · 작업은 방 하나로 옮김

### 체험 방 — 평가자가 코드 없이 들어오는 방

**왜** — 최종 결과물이 배포 주소라, 평가자는 주소만 받고 처음 들어옵니다. 우리 방의 코드를 모르니 새 방을 만들 수밖에 없고, 빈 방에서는 팀원 세 명 등록 · 작업 · 세 명분 추정까지 혼자 해야 핵심 기능이 보입니다. 그래서 **데이터가 미리 채워진 공개 방**을 하나 둡니다.

| 규칙 | 내용 |
|---|---|
| 들어가는 법 | 입장 화면에 **`체험 방으로 들어가기`** 버튼. 코드는 고정 `DEMO` (사람이 치지 않으므로 코드 형식 규칙의 예외) |
| 이름 | 새 이름을 받지 않고 **예시 팀원 중 한 명을 골라** 들어감. 같은 이름 거부 · 정원 규칙은 체험 방에 적용하지 않음 — 평가자가 들어올 때마다 팀원이 늘면 추정이 공개되지 않기 때문 |
| 처음 상태 | 저장소에 커밋한 `seed/demo.json` (예시 데이터라 공개해도 됨. `data/` 는 커밋하지 않으므로 다른 폴더) |
| 되돌리기 | 서버를 켤 때마다 체험 방을 처음 상태로. 하루 한 번 컨테이너를 다시 켜 평가자가 바꾼 것을 지움 |
| 안내 | 체험 방 머리말에 `체험 방입니다. 바꾼 내용은 하루 뒤 처음 상태로 돌아갑니다.` |

**처음 상태에 넣을 것** — 평가자가 버튼 하나로 들어와 모든 화면이 비어 있지 않게.

| 화면 | 들어 있어야 할 상태 | 누가 내용을 정함 |
|---|---|---|
| 작업 정의 | 추정 진행 중(2 / 3 제출 — 평가자가 남은 한 명으로 내면 공개되는 것을 직접 볼 수 있게) · 공개됐고 `의견 차이 큼` · 크기 확정 · AI 로 나눈 상위 작업과 세부 작업 | A |
| 분배 | 크기는 정해졌고 담당 미정인 작업 2개(추천을 눌러 볼 수 있게) · 과부하에 가까운 팀원 1명 | B |
| 등록 · 진행 | 할 일 · 진행 중 · 완료 칸이 모두 차 있음 · 지난 마감 1개 · 이번 주 · 지난주 마감 작업(주차별 수행률) | C |

### B 가 까는 뼈대 (1단계, 11/23까지)

**뼈대만으로 처음부터 끝까지 동작해야 합니다.** 다른 사람 라우트는 B 가 바꾸지 않고, 바꿔도 깨지지 않게 둡니다.

| 무엇 | 파일 |
|---|---|
| 방 단위 저장 `loadRoom` · `saveRoom` + 기존 데이터 옮기기 | `src/lib/store.js` |
| 방 API — 만들기 · 입장 확인 · 이름으로 입장 (아래 표) | `src/routes/rooms.js` (새 파일) |
| 공용 미들웨어 — `X-Room-Code` 를 읽어 `req.roomCode` 에 넣음. 없으면 400, 없는 방이면 404 | `src/app.js` |
| `api.js` 가 모든 요청에 방 코드를 붙이고, 입장 전이면 입장 화면으로 보냄 | `public/js/api.js` (C 파일 — C 에게 말하고 따로 커밋) |
| 동작만 하는 입장 화면 — 코드 입력 · 방 만들기(팀명 · 팀원 수) · 이름 입력 | `public/enter.html` · `public/js/enter.js` (새 파일. 모양은 A 가 2단계에 다듬음) |
| 기존 `load()` · `save()` 는 **당분간 첫 번째 방**을 읽고 쓰게 둠 | 각자 2단계에 바꾸기 전까지 기존 라우트가 깨지지 않게 |
| 체험 방 장치 — 고정 코드 `DEMO`, 서버를 켤 때 `seed/demo.json` 으로 되돌리기, 예시 팀원 골라 입장 (`POST /api/rooms/DEMO/join { memberId }`) | `src/lib/store.js` · `src/routes/rooms.js`. 처음 상태의 **내용**은 2단계에 세 명이 채움 |

```js
// data/db.json
{ rooms: { 'K7MQ2X': { name: '할래말래 팀', size: 3, members: [], tasks: [], createdAt } } }

// store.js — 라우트는 지금 쓰던 { members, tasks } 모양을 그대로 받는다
export function loadRoom(code)        // 없는 코드면 null
export function saveRoom(code, room)
```

| 경로 | 하는 일 |
|---|---|
| `POST /api/rooms { name, size }` | 방 생성 → `{ code, name, size }` (201) |
| `GET /api/rooms/:code` | 입장 확인 → `{ code, name, size, memberCount }` / 404 |
| `POST /api/rooms/:code/join { name }` | 이름으로 입장 → `Member` (201). 같은 이름 400, 정원 초과 400 (검사는 C 의 `validateMember` 재사용) |
| 나머지 `/api/*` | `X-Room-Code` 헤더 필수 |

### 각자 바꾸는 것 (2단계)

자기 라우트에서 이 두 줄만 바꿉니다.

```js
const db = load();          →  const db = loadRoom(req.roomCode);
save(db);                   →  saveRoom(req.roomCode, db);
```

| 누가 | 라우트 | 화면 |
|---|---|---|
| A | `estimates` · `breakdown` | 추정의 "누구" 칸 없애기, 입장 화면 다듬기 |
| B | `loads` · `recommend` | — |
| C | `members` · `tasks` · `progress` · `weekly` | 머리말 팀명 · 이름 · `나가기` |

세 명이 다 바꾸면 B 가 `load()` · `save()` 의 "첫 번째 방" 임시 처리를 지웁니다.

**지키는 원칙** — 비밀번호 · 개인정보는 받지 않습니다. 입장 코드는 "이 팀의 공간을 여는 열쇠"일 뿐 계정이 아닙니다. README 원칙 4의 "로그인이 없다" 문구는 이렇게 고칩니다.

## 6. 배포 — AWS EC2 + Docker, 수동 배포

**공지 (수업)** — 최종 결과물은 **배포된 서비스 주소(URL)**. Docker 배포는 **권장, 필수 아님**. Vercel 처럼 배포를 자동으로 처리하는 서비스는 쓰지 않음.

**정한 구성** — 7조가 같은 조건(Express · JSON 파일 저장 · 자동 배포 금지)으로 이미 배포한 구성을 따릅니다. 만든 순서가 [7조 docs/deploy.md](https://github.com/cjs1004ounds/oss-teamproject/blob/main/docs/deploy.md)에 있어 그대로 참고합니다.

| 항목 | 선택 | 이유 |
|---|---|---|
| 서버 | AWS EC2 한 대 (서울 리전, t3.micro) | 가상 서버를 직접 운영 → 자동 배포 규칙에 맞음. 7조 가이드를 따라 할 수 있음 |
| 실행 | Docker 컨테이너, 메모리 512MB 제한 | 권장 사항. 의존성이 Express 하나라 `Dockerfile` 20줄 정도 |
| 데이터 | 컨테이너 밖 볼륨에 `db.json` (`DATA_DIR`) | 컨테이너를 새로 만들어도 데이터가 남음 |
| 주소 | 무료 도메인(duckdns) + nginx 로 https | 결과물이 주소라 기억하기 쉬운 주소와 https |
| 배포 | `main` 병합 뒤 서버에 접속해 직접 다시 빌드 · 실행 | 자동 배포 아님. GitHub Actions 는 테스트만 |

**쓰지 않는 것** — Vercel · Render · Netlify · Railway 처럼 GitHub 에 연결해 자동으로 배포하는 서비스. Render 무료는 재시작 때 파일이 지워지고 15분 쉬면 잠들어 평가자가 첫 화면을 1분 기다림.

**대안** — AWS 가입이 막히면 Oracle Cloud Always Free 가상 서버에 **같은 방식(Docker + 볼륨)** 으로 올림.

**알아둘 것**

- AWS 신규 계정의 무료 조건(크레딧 · 무료 플랜 기간)은 가입 전에 공식 페이지에서 확인하고, **예산 알림**을 꼭 걸어 둠
- 최종 결과물이 주소라 **평가가 끝날 때까지 서버가 켜져 있어야 함**
- `.env`(Gemini 키)는 서버에만. 저장소와 Docker 이미지에 넣지 않음

**순서 (B)**

| # | 할 일 | 언제 |
|---|---|---|
| 1 | `store.js` 저장 경로를 `DATA_DIR` 환경 변수로 바꿀 수 있게 (기본은 지금처럼 `data/`) + `Dockerfile` | 1단계 |
| 2 | 내 컴퓨터에서 `docker build` · `docker run`(볼륨 · `--memory 512m` · `TZ=Asia/Seoul`)으로 먼저 확인 | 1단계 |
| 3 | EC2 만들기, 보안 그룹은 80 · 443만, duckdns 주소 연결, nginx + https 인증서 | 1단계 |
| 4 | 서버에서 같은 명령으로 실행, `--restart unless-stopped` 로 재부팅해도 다시 뜨게 | 1단계 |
| 5 | 업데이트: 서버 접속 → `git pull` → 이미지 다시 빌드 → 컨테이너 교체 (수동) | 2단계부터 매 병합 뒤 |
| 6 | 하루 한 번 볼륨의 `db.json` 을 복사해 두는 백업 | 2단계 |
| 7 | README 에 배포 주소와 다시 올리는 법 | 2단계 |
