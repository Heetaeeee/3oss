# 화면 디자인 가이드

세 명이 각자 자기 자리를 그려도 한 사람이 만든 화면처럼 보이게 하기 위한 공용 규칙입니다.
완성된 모습은 [design-mockup.html](design-mockup.html)을 브라우저로 열어 확인하세요. 오른쪽 위 **담당 구역 표시**를 켜면 누가 어디를 그리는지 보입니다.

## 한눈에

- **분위기** — 부드럽고 친근한 팀 도구. 옅은 푸른 바탕 위에 둥근 흰 면을 올리고, 테두리와 그림자 없이 밝기 차이로만 구역을 나눕니다. 그라데이션 장식 · 이모지 아이콘은 쓰지 않습니다.
- **색은 뜻입니다** — 파랑은 누를 수 있는 것과 계산된 값, 초록은 팀이 정한 것, 노랑은 AI가 제안한 것, 빨강은 넘침과 오류. README 다이어그램의 노랑 · 초록과 같은 뜻입니다.
- **막대는 하나** — 부담률 · 예상 부담률 · 진행률 · 완료 작업 비중이 모두 같은 `.bar` 를 씁니다. 이 화면에서 가장 눈에 띄어야 하는 것은 100% 세로선입니다.
- **사람은 칩으로** — 팀원 이름 앞에는 항상 성 한 글자가 든 동그란 칩이 붙고, 같은 사람은 어디서나 같은 색입니다.
- **새 색 · 새 크기를 만들지 않습니다** — 아래 토큰과 공용 클래스로 안 되는 경우에만 추가하고, 추가하면 이 문서에 적습니다.

## 원칙 다섯

| | 원칙 | 이유 |
|---|---|---|
| 1 | 색만으로 뜻을 전하지 않는다. 항상 글자가 함께 있다 | `120% 과부하`, `지남 1일`, `의견 차이 큼` — 색을 못 봐도 읽힌다 |
| 2 | 초록은 버튼이 아니라 **결과**다 | "팀이 정했다"는 표시. 누르는 것은 파랑 하나로 통일 |
| 3 | 노랑은 AI가 **실제로 제안했을 때만** | 실패 · 키 없음 상태는 일반 패널. AI가 관여한 곳이 한눈에 구분된다 |
| 4 | 한 구역에 진한 파란 버튼(`.btn--primary`)은 하나 | 다음에 누를 것이 하나로 보인다. 나머지는 옅은 파랑(`.btn`) |
| 5 | 아직 정하지 않은 것은 점선 배지 | `크기 미정` · `담당 미정` — 보드에서 "남은 결정"이 바로 보인다 |

## 토큰

`public/style.css` 의 `:root` 에 두 층으로 둡니다. 위층은 **원시값**(`--blue-600` 같은 색 그 자체), 아래층은 **뜻**(`--primary` 같은 쓰임새)입니다.
**화면 코드는 뜻 변수만 씁니다.** 색 코드(`#…`)는 원시값 줄에만 있고, 분위기를 바꿀 때는 그 줄만 고치면 됩니다.

| 뜻 변수 | 값 | 쓰는 곳 |
|---|---|---|
| `--bg` | `#EEF2F7` | 페이지 바탕, 상태 선택칸 |
| `--surface` | `#FCFDFF` | 패널 · 카드 · 입력칸 |
| `--ink` | `#1F2733` | 본문 글자, 100% 세로선 |
| `--sub` | `#5E6875` | 보조 글자, 라벨 |
| `--line` | `#CFD7E2` | 입력칸 테두리 |
| `--track` | `#E1E7EF` | 막대 바닥, 기본 배지, 카드 안 구분선 |
| `--primary` / `--primary-strong` / `--primary-bg` | `#2A63E8` / `#1F4FC4` / `#E3ECFD` | 주 버튼 · 막대 · 포커스 / 보조 버튼 글자 · 눌린 주 버튼 / 보조 버튼 · `추천` 배지 |
| `--on-primary` | `#FCFDFF` | 진한 색 위의 글자 |
| `--team-bg` / `--team-ink` | `#DFF3E4` / `#1F6B35` | 확정된 크기, 배정된 담당자 |
| `--ai-bg` / `--ai-ink` | `#FFF3CC` / `#6B4E00` | AI 세분화 패널, `AI 제안` 배지 |
| `--over` / `--over-ink` / `--over-bg` | `#D63B30` / `#B42A20` / `#FDE9E7` | 막대의 넘친 부분 · 오류 테두리 / 빨간 글자 / 빨간 배지 바탕 |
| `--m1` ~ `--m6` | 연보라 · 민트 · 분홍 · 살구 · 하늘 · 모래 | 팀원 칩 바탕. 등록 순서대로 |
| `--r-s` / `--r-m` / `--r-l` / `--r-pill` | `12px` / `16px` / `20px` / `999px` | 버튼 · 입력칸 / 카드 / 패널 / 배지 · 막대 |
| `--s1` ~ `--s6` | `4 · 8 · 12 · 16 · 24 · 32px` | 모든 여백. 이 여섯 값만 |
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | 모든 움직임 |

모든 글자색 조합은 명도 대비 4.5:1 이상으로 골랐습니다. 새 조합을 만들면 대비를 확인하세요.

**글자** — `Pretendard` (없으면 시스템 글꼴). `--font` 변수로만 지정합니다. 글꼴을 불러오는 `<link>` 는 목업 `<head>` 에 있는 것을 우희태가 `index.html` 에 넣습니다.

| 크기 | 쓰는 곳 |
|---|---|
| 28px / 700 | 서비스 이름 (`h1`) |
| 20px / 700 | 구역 제목 (`h2`) |
| 16px / 600 | 카드 제목 · 작은 제목 (`h3`), 숫자 (`strong`) |
| 16px / 400 | 본문, 입력칸 |
| 14px / 400 | 보조 설명 (`.sub`), 입력 라벨, 오류 문장 |
| 13px / 600 | 배지, 팀원 칩 |

숫자는 `tabular-nums` 로 자릿수 폭을 맞춥니다(`body` 에 이미 걸려 있음). 13px 보다 작은 글자는 쓰지 않습니다.

## 화면 배치

페이지는 하나입니다. 왼쪽은 **작업**(무엇을), 오른쪽은 **팀**(누가 · 얼마나).

```
넓은 화면 (900px 초과)
┌──────────────────────────────────────────────────────────┐
│ 3oss  한 줄 소개                                          │
├───────────────────────────────────────┬──────────────────┤
│ 작업 등록                         (C) │ 팀원 #members (C)│
├───────────────────────────────────────┤                  │
│ 큰 작업 나누기 #breakdown         (A) ├──────────────────┤
├───────────────────────────────────────┤ 부담률 #load  (B)│
│ 작업 보드 #tasks                  (C) │                  │
│ ┌ 할 일 (넓게) ─┐ ┌ 진행 중 ┐ ┌ 완료 ┐ ├──────────────────┤
│ │ 카드          │ │ 카드    │ │ 카드 │ │ 진행 현황        │
│ │  └ sizing (A) │ │         │ │      │ │ #progress     (C)│
│ │  └ recommend(B)│ │         │ │      │ │                  │
│ └───────────────┘ └─────────┘ └──────┘ │                  │
└───────────────────────────────────────┴──────────────────┘

좁은 화면 (900px 이하)          640px 이하
왼쪽 → 오른쪽 순으로 한 줄        보드의 세 칸도 세로로
```

- 최대 폭 1200px, 오른쪽 칸 340px 고정.
- '할 일' 칸이 가장 넓습니다(1.6 : 1 : 1). 추정과 추천이 모두 여기서 열리기 때문입니다.
- 패널(`.panel`)은 흰 면이고, 작업 보드는 패널 없이 바탕 위에 카드(`.card`)를 바로 올립니다. **흰 면 안에 흰 면을 또 넣지 않습니다.**
- 구역 사이는 `--s5`, 구역 안은 `--s3`. 세로로 쌓을 때는 `.stack`, 가로로 놓을 때는 `.row` · `.between` 을 쓰고 `margin` 을 따로 주지 않습니다.

### 작업 카드 — 세 명이 함께 쓰는 유일한 곳

```
┌────────────────────────────────────┐
│ 작업 제목                 [상태 ▾] │  C
│ (D-8) (4시간 확정) (담당 미정)     │  C  ← 배지 순서 고정: 마감 → 크기 → 담당
├────────────────────────────────────┤
│ [data-slot="sizing"]               │  A  ← 크기가 확정되면 비운다
├────────────────────────────────────┤
│ [data-slot="recommend"]            │  B  ← 크기 확정 + 담당 미정일 때만 채운다
└────────────────────────────────────┘
```

- 슬롯은 `class="slot stack"` 을 달면 위 구분선과 간격이 생깁니다. **비어 있으면 자동으로 사라지므로**(`[data-slot]:empty`) 보여줄 것이 없을 때는 내용을 완전히 비우세요.
- 슬롯 안 첫 줄은 항상 `h3` 제목(`크기 추정` · `담당자 추천`)입니다.
- 카드 하나에 두 슬롯이 동시에 열리지 않습니다. 순서가 추정 → 추천이기 때문입니다.

## 공용 부품

전부 `public/style.css` 에 있습니다. 마크업은 목업 파일에서 복사하세요.

| 부품 | 클래스 | 규칙 |
|---|---|---|
| 패널 | `.panel` | 구역 하나. 테두리 · 그림자 없음 |
| AI 패널 | `.panel.panel--ai` | AI가 제안한 내용을 담을 때만 |
| 카드 | `.card` | 작업 하나 |
| 버튼 | `.btn` (옅은 파랑) · `.btn--primary` (진한 파랑) · `.btn--quiet` (글자만) · `.btn--s` | 높이 44px(작은 것 40px). 글자는 누르면 일어나는 일 그대로 — `작업 등록` · `추정 제출` · `크기 확정` · `배정` |
| 입력칸 | `label.field > input` | 높이 44px. 라벨은 항상 입력칸 위에 보이게. placeholder 는 예시만, 도움말은 아래 `p.sub` |
| 팀원 칩 | `span.who > span.avatar.avatar--N + 이름` | N은 등록 순서(1~6, 일곱 번째부터 다시 1). 칩에는 `aria-hidden="true"` |
| 오류 | `.field.is-error` + `p.msg-error[role=alert]` | 서버의 `error` 문장을 입력칸 바로 아래에 그대로 |
| 배지 | `.badge` + `--todo` · `--team` · `--primary` · `--ai` · `--over` | 아래 표 |
| 막대 | `.meter > .between + .bar > .bar-now` | 아래 |
| 빈 상태 | `p.sub` | 무엇이 없는지 + 다음에 할 일 한 문장 |

**배지**

| 모양 | 뜻 | 예 |
|---|---|---|
| 회색 `.badge` | 중립 정보 | `D-8` · `1 / 3 제출` · `직접 입력` |
| 점선 `--todo` | 아직 정하지 않음 | `크기 미정` · `담당 미정` |
| 초록 `--team` | 팀이 정함 | `4시간 확정` · `담당 박지호` |
| 파랑 `--primary` | 계산 결과 | `추천` |
| 노랑 `--ai` | AI가 제안 | `AI 제안` |
| 빨강 `--over` | 넘침 · 주의 | `지남 1일` · `의견 차이 큼` |

**막대** — JS는 `--v` 에 숫자만 넣습니다. 폭 · 색 · 100% 초과분의 빨강은 CSS가 계산합니다.

```html
<div class="meter">
  <div class="between">
    <span class="who"><span class="avatar avatar--1" aria-hidden="true">박</span>박지호</span>
    <strong>30% → 70%</strong>
  </div>
  <div class="bar" role="img" aria-label="현재 30%, 맡으면 70%">
    <span class="bar-next" style="--v:70"></span>   <!-- 빗금: 맡았을 때 예상. 없으면 생략 -->
    <span class="bar-now" style="--v:30"></span>    <!-- 채움: 현재 -->
  </div>
</div>
```

| 종류 | 클래스 | 눈금 |
|---|---|---|
| 부담률 | `.bar` | 0 ~ 150%, 세로선이 100%. 넘은 부분은 빨강 + 글자 `과부하` |
| 진행률 · 완료 작업 비중 | `.bar.bar--100` | 0 ~ 100%, 세로선 없음 |

숫자 표기는 README 형식 그대로: `30%`, `30% → 70%`, `120% 과부하`, `22% · 2건 / 9건`, `50% · 3시간 / 6시간`, `배정 불가`.

## 움직임

장식용 애니메이션은 없습니다. 사용자의 행동에 답하는 두 가지만 있고, 둘 다 공용 스타일에 이미 들어 있습니다.

| 무엇 | 값 | 이유 |
|---|---|---|
| 버튼을 누를 때 | `transform: scale(0.97)`, 160ms | 눌렸다는 즉각적인 반응 |
| 막대 값이 바뀔 때 | `clip-path` 250ms | 배정 · 완료 뒤 무엇이 바뀌었는지 보인다 |

- `transition: all` 을 쓰지 않고, `width` · `height` · `top` · `left` 를 움직이지 않습니다. 막대도 폭이 아니라 `clip-path` 로 움직입니다.
- 마우스 올림 효과는 `@media (hover: hover) and (pointer: fine)` 안에서만 줍니다(휴대폰에서 눌린 채 남는 것 방지).
- `prefers-reduced-motion: reduce` 에서는 둘 다 꺼집니다. 새 움직임을 넣으면 여기에도 추가하세요.
- 새로 그려지는 목록 · 패널에 등장 애니메이션을 넣지 않습니다. `refresh()` 때마다 다시 재생되어 느려 보입니다.

## 문구

- 해요체가 아니라 **합니다체**, 문장 끝에 마침표. 버튼과 배지에는 마침표를 붙이지 않습니다.
- 사용자에게 보이는 말은 README의 용어를 씁니다 — 부담률, 가능한 시간, 크기, 확정, 배정, 과부하. `load` · `hours` · `TODO` 같은 코드 이름을 화면에 내지 않습니다.
- 상태 이름은 `할 일` · `진행 중` · `완료`.
- 오류는 사과하지 않고 고칠 점을 말합니다 — `가능한 시간은 0 이상의 숫자로 입력하세요.`
- 사람 이름 뒤에는 `님` — `박지호 님이 맡으면 …`
- 이름 · 제목은 반드시 `textContent` 로 넣습니다(`innerHTML` 금지). `<b>굵게</b>` 가 글자 그대로 보여야 합니다.

## 접근성 · 반응형 최소선

- 키보드만으로 모든 버튼 · 입력칸에 닿고, 포커스 테두리(`:focus-visible`)를 지우지 않습니다.
- 누르는 것은 `<button>`, 입력은 `<label>` 안에. `div` 에 클릭을 달지 않습니다.
- 막대에는 `role="img"` 와 숫자를 읽어 주는 `aria-label`.
- 누를 수 있는 것은 높이 40px 이상, 서로 8px 이상 떨어뜨립니다.
- 아이콘이 필요해지면 이모지가 아니라 SVG 를 쓰고, 글자 없이 아이콘만 있는 버튼에는 `aria-label` 을 답니다.
- 폭 375px 에서 가로 스크롤이 생기지 않아야 합니다. 고정 `width` 대신 `.row` 의 줄바꿈에 맡기세요.

## 담당별 가이드

### 공용 스타일 — 김권섭

`public/style.css` 와 이 문서의 주인입니다. 공용 부품 · 토큰을 바꾸고 싶으면 김권섭에게 말하고, 바뀐 내용은 이 문서에도 반영합니다.

- `style.css` 는 목업의 첫 번째 `<style>` 블록("공용 스타일")을 그대로 옮기는 것으로 시작합니다. 두 번째 블록("목업 전용")은 옮기지 않습니다.
- C의 `index.html` 뼈대와 같은 시점(반나절 안)에 올립니다.

### C 우희태 — 뼈대와 등록 · 진행 관리

- `index.html` 은 목업의 구역 순서와 id 를 그대로 — `#members` · `#tasks` · `#progress` · `#breakdown` · `#load`.
- 작업 카드를 그릴 때 **빈 슬롯 두 개를 항상 넣어 줍니다** — `<div class="slot stack" data-slot="sizing" data-task-id="t1"></div>` 와 `recommend`. A · B가 여기를 찾아 채웁니다.

| 자리 | 그리는 것 | 주의 |
|---|---|---|
| 작업 등록 | 제목 + 마감일 + `작업 등록`(primary) | 오류 문장은 입력칸 아래 |
| `#members` | 팀원 칩 + 이름 · `이번 주 10시간` · `수정`(quiet) 목록, 아래에 등록 폼 | 등록 버튼은 기본 `.btn` (이 화면의 주 행동은 작업 등록). 칩 색 번호는 목록 순서 — A · B도 같은 순서를 씁니다 |
| `#tasks` | 세 칸 보드. 칸 제목 옆에 개수 | 배지 순서 고정. 미정은 점선, 확정은 초록. 완료 카드에는 D-day 를 빼기 |
| D-day | `D-8` 회색, `D-day` 회색, 지나면 `지남 1일` 빨강 | 마감일이 없으면 배지 자체를 넣지 않음 |
| `#progress` | 전체 진행률 `.bar--100` + 완료 작업 비중 막대 | 맨 아래에 `확정한 예상 시간 기준입니다. 실제 기여와 다를 수 있습니다.` |

### A 김권섭 — 작업 정의

노랑을 쓰는 유일한 사람입니다.

**`#breakdown`**

| 상태 | 모양 |
|---|---|
| 처음 | 일반 `.panel`. 제목 입력 + `AI로 나누기` |
| 불러오는 중 | 버튼 `disabled`, 글자 `나누는 중…` |
| 제안 도착 (`source: 'ai'`) | `.panel--ai` 로 바뀌고 `AI 제안` 배지, 체크박스 목록, `고른 3개 등록`(primary, 개수 반영). 0개를 고르면 `disabled` |
| 실패 · 키 없음 (`'fallback'`) | 일반 `.panel` 유지, `직접 입력` 회색 배지, 안내 문장 + 제목 입력칸 |

패널 아래에 항상 `작업 제목만 AI에 보냅니다. 팀원 이름과 시간은 보내지 않습니다.`

**`[data-slot="sizing"]`**

```
① 제출 받는 중                         ② 전원 제출 → 공개
┌──────────────────────────────┐      ┌──────────────────────────────┐
│ 크기 추정        (1 / 3 제출)│      │ 크기 추정      (의견 차이 큼)│
│ 김권섭 님이 제출했습니다. …   │      │ 김권섭  3시간  근거          │
│ [누구의 추정 ▾] [예상 시간]  │      │ 박지호  4시간  근거 없음     │
│ [근거 (선택)              ]  │      │ 우희태  8시간  근거          │
│ [추정 제출]                  │      │ [확정 크기 — 중앙값 4] [크기 확정]│
└──────────────────────────────┘      └──────────────────────────────┘
③ 확정 뒤 → 슬롯을 비운다. 카드의 `4시간 확정` 초록 배지(C)가 결과를 보여 준다
```

- ①에서는 **누가 냈는지만** 보이고 숫자는 어디에도 그리지 않습니다.
- ②의 `의견 차이 큼` 은 빨강 배지, 차이가 없으면 배지 없음. 확정 입력칸에는 중앙값을 미리 채워 두고, 아래에 `중앙값인 4시간을 미리 넣어 두었습니다. 이야기해 보고 바꿔도 됩니다.`
- 추정 목록은 `.est` (팀원 칩 + 이름 · 시간 · 근거 세 칸).

### B 박지호 — 분배

막대의 주인입니다. `.bar` 가 어색하면 고쳐서 C에게 알려 주세요.

**`#load`** — 팀원마다 `.meter` 하나. 등록 순서대로.

| 경우 | 숫자 자리 | 막대 |
|---|---|---|
| 보통 | `60%` | 파랑 |
| 100% 초과 | `120% 과부하` 빨강 글자 | 세로선 뒤가 빨강 (자동) |
| 가능한 시간 0 (`load: null`) | `배정 불가` 보조 글자, 막대 아래에 `가능한 시간이 0시간입니다.` | 빈 막대 |

맨 아래에 `세로선이 가능한 시간의 100%입니다. 넘으면 과부하로 표시합니다.`

**`[data-slot="recommend"]`**

```
┌────────────────────────────────────────┐
│ 담당자 추천                            │
│ 박지호 님이 맡으면 부담률이 30% → 70%… │ ← 서버의 explanation 그대로, 본문 크기
│ 박지호 (추천)     30% → 70%   [배정]   │ ← 추천된 사람만 primary 버튼
│ ▓▓▓▒▒▒▒░░░│░░░                         │
│ 김권섭            60% → 100%  [배정]   │ ← 나머지는 기본 버튼
│ 우희태            80% → 120% 과부하 [배정] │ ← 과부하여도 고를 수 있다
│ 추천은 참고 자료입니다. 담당자는 팀이 정합니다. │
└────────────────────────────────────────┘
```

- 후보는 서버가 준 순서(예상 부담률 오름차순) 그대로. 한 줄은 `.pick` (막대 + 버튼).
- 제외된 팀원은 목록 아래에 보조 글자로 — `제외: 새 팀원 (가능한 시간 0시간)`.
- 후보가 없으면 설명 문장만 보여 주고 버튼을 그리지 않습니다.
- 배정이 끝나면 슬롯을 비웁니다. 카드의 `담당 박지호` 초록 배지(C)가 결과를 보여 줍니다.

## CSS 를 나눠 쓰는 법

- 공용 부품만으로 그리는 것이 기본입니다. 목업 화면은 전부 공용 클래스만으로 만들었습니다.
- 자기 구역에만 필요한 스타일이 생기면 `style.css` 맨 아래에 `/* A — sizing */` 처럼 **자기 주석 구역**을 만들어 그 안에만 씁니다. 남의 구역은 그 담당자에게, 공용 부분은 김권섭에게 고치기 전에 말합니다.
- JS에서 `element.style` 로 넣어도 되는 것은 막대의 `--v` 뿐입니다. 색 · 크기는 클래스로 바꿉니다.

## PR 올리기 전에

- [ ] 색 · 글꼴 · 간격 · 모서리를 변수로만 썼다 (`#` 로 시작하는 색, `px` 여백을 새로 쓰지 않았다)
- [ ] 팀원 이름 앞에 칩이 있고, 색 번호가 팀원 목록 순서와 같다
- [ ] `transition: all` 이 없고, 새 움직임은 `prefers-reduced-motion` 에서 꺼진다
- [ ] 빨강 · 초록 · 노랑 옆에 같은 뜻의 글자가 있다
- [ ] 내 구역에 파란 버튼이 하나다
- [ ] 비어 있을 때 · 오류일 때 모양이 목업의 "상태 모음"과 같다
- [ ] Tab 키로 끝까지 갈 수 있고 포커스가 보인다
- [ ] 폭 375px 에서 가로 스크롤이 없다
- [ ] 이름에 `<b>굵게</b>` 를 넣어도 글자 그대로 보인다
